# Aurum Vision — Data Sources

Every dataset used to train **Aurum Vision v0.1**, with the license and
statistics reported by the source platform at download time.

> This file is generated by `python scripts/gen_data_sources.py` from
> `data/raw/*/_aurum_meta.json` (written verbatim from the Roboflow
> project metadata API) and `reports/dataset_stats.json`. The numbers are
> not transcribed by hand.

## Summary

- **6 source datasets**, all from Roboflow Universe
- **17,193 images** downloaded (includes Roboflow's augmented copies)
- **9,823 annotations** mapped into Aurum classes; **18,086** explicitly dropped
- Final classes: **PCB, RAM, CPU, Connector**
- Licenses present: **CC BY 4.0, Public Domain**

## Datasets found and deliberately excluded

Recorded so the exclusion is reviewable rather than invisible.

- **`james-manalili/pc-components-tfwjg`** — Exact duplicate of pro-elect-4-6fbgr/pc-components-mvkie — identical image count (978), identical train/valid/test split sizes (782/98/98) and identical per-class instance counts across all 12 classes. Including both would put the same photographs in train and test.
- **`cas-pc-project/pc-parts-detection-yajmi`** — Same 12-class vocabulary and near-proportional class counts (~42% of mvkie across every class), consistent with being a re-upload of a subset of the same source images. Excluded as a leakage risk.
- **`computer-vision-assembly-instructions/computer-hardware`** — 2,370 images with usable ram/cpu labels, but the project exposes no generated versions via the API, so there is no reproducible export to pin. Cannot be included without an unpinnable manual download.
- **`roboflow-100/printed-circuit-board`** — Measured before exclusion: median annotation is 1.27% of the image side (~8 px at 640), i.e. microscope/flatbed-scale SMD inspection. The Connector boxes are real but at a scale a webcam at arm's length cannot resolve, so training on them would not transfer to the demo. Also, its class 0 `printed-circuit-board` has zero instances — a phantom class from the Roboflow export, not a usable whole-board label.
- **`universe.roboflow.com/mylab/pcb-colab`** — Same SMD inspection scale as roboflow-100/printed-circuit-board.

## Label normalization

The full map lives in `configs/aurum_labels.yaml` (version 0.1). Matching is on a normalized key, so `RAM stick`, `ram_stick` and `Ram-Stick` all resolve to the same alias.

A source label must be either mapped or explicitly dropped with a
reason; an unreviewed label raises an error during preparation rather
than being silently discarded.

### Class definitions

- **PCB** — A whole printed circuit board as a single object: motherboards, graphics cards, expansion cards, and bare/populated boards photographed as one item. The box covers the board outline, not the components mounted on it.
- **RAM** — A memory module as a whole object — DIMM, SO-DIMM, or server RDIMM. The distinguishing feature is the long thin PCB with a gold edge connector and a row of identical memory chips.
- **CPU** — A packaged processor as a whole object — LGA, PGA, or BGA package, with or without a heat spreader. Includes the pin/pad underside view.
- **Connector** — A physical mating interface: headers, sockets, slots, ports, edge connectors, and pin blocks. This is the class most associated with plated gold contacts, which is why it is tracked separately from PCB.

## Notable class decisions

- **`gpu` was dropped despite being the largest available label (~2,800 instances).** In every source dataset a `gpu` is an assembled graphics card whose camera-facing surface is a cooler shroud, not an exposed board. Merging it into PCB would train the model that plastic shrouds are circuit boards and would corrupt PCB counts in batch records.
- **`ic` was not merged into CPU.** An `IC` annotation covers every integrated circuit on a board — regulators, controllers, flash. Folding these into CPU would make the CPU count in a batch record meaningless.
- **`ram_slot`, `gpu_slot` and `rear_io` were merged into Connector.** A DIMM socket, a PCIe socket and a rear port bank are all mating interfaces with plated contacts, and they are the only source of whole-object Connector boxes at a scale a webcam resolves.
- **`battery` was considered as a fifth class and rejected.** The available annotations span 9V cells, coin cells, laptop packs and RC LiPo packs, which are not one visual category.

## Splits and leakage control

- 17,193 images hashed; 5,146 source-stem groups merged into **4,353 duplicate clusters** (310 near-duplicate merges at Hamming ≤ 5).
- Splits are assigned over **clusters, never images**, so augmented copies and re-uploads of one photograph cannot straddle train and test.
- 3,233 augmented copies were removed from valid/test so held-out counts reflect unique scenes.
- 8,464 background-only images dropped (capped so they cannot drown the labelled objects).

| split | images | PCB | RAM | CPU | Connector |
|---|---|---|---|---|---|
| train | 4,878 | 1,223 | 3,256 | 1,470 | 927 |
| valid | 412 | 138 | 254 | 172 | 107 |
| test | 206 | 69 | 139 | 79 | 53 |

Verified by `python -m ml.validate`, which independently re-checks for cluster containment, exact duplicates and perceptual near-duplicates across splits. See `reports/dataset_validation.json`.
